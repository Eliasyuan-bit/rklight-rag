# RAG 问答性能基线（2026-09-21）

> 历史单次/首轮基线，保留作原始记录；**不作为稳定态性能结论**。各模式预热后、临时关闭 LLM 缓存的多次复测见[稳定态对比](rag-naive-vs-mix-performance.md)。两组样本的热身与缓存状态不同，不可混合计算。

测试对象：板端当前三文档知识库，LightRAG `mix` 查询、rerank 开启、Qwen3.5-2B 查询模型。9 道固定题单客户端串行，各运行一次；另对“FT 测试中 USB 错误是为什么？”分别测当前缓存路径和临时关闭 LLM 缓存的完整路径。请求均为空会话历史。端到端时间由客户端单调时钟测量，LLM token 数由 RKLLM 原生 `usage` 返回。

板端时钟当时显示 `2026-04-27`，与操作环境日期不一致；JSON 中的绝对时间戳受此影响，毫秒耗时使用单调时钟，不受影响。

## USB 错误问题的阶段耗时

同一句“FT 测试中 USB 错误是为什么？”、同一查询参数，各测一次：

| 阶段 | 当前缓存路径 | 关闭 LLM 缓存 |
| --- | ---: | ---: |
| 关键词 LLM | 缓存复用，0 次 | 1 次；662 输入 / 41 输出 token；976.4 ms |
| Embedding | 1 次；102.8 ms | 1 次；92.6 ms |
| Rerank | 1 次；727.4 ms | 1 次；733.1 ms |
| 最终回答 LLM | 1 次；1188 输入 / 117 输出 token；2420.9 ms | 1 次；1188 输入 / 117 输出 token；2230.3 ms |
| 端到端首字时间 | 2266.4 ms | 3680.1 ms |
| 端到端总耗时 | 3455.8 ms | 4860.1 ms |

Embedding 这次输入 3 条文本、共 48 个字符，输出向量为 1024 维；rerank 对 6 个候选做排序，候选文本合计 3455 个字符。向量模型当前接口没有返回 tokenizer 的 token 计数，所以这两阶段只报告实际调用次数、耗时、输入项与候选规模。表中的阶段耗时是网关内单次调用耗时，不能直接当作端到端时间的互斥分解；其余时间涉及检索、LightRAG 处理和传输。关闭缓存只对本次测试进程生效，测试后已恢复原服务配置。

## 同一问题的 Naive RAG 单次实测

同一句“FT 测试中 USB 错误是为什么？”切换为 `naive` 模式后，实际只调用最终回答
LLM，没有关键词提取 LLM：

| 阶段 | Naive RAG 实测 |
| --- | ---: |
| 查询理解 LLM | 不调用 |
| Query Embedding | 30.6 ms；1 条文本、18 字符、1024 维 |
| 向量检索与 Top-K | 当前没有独立计时点 |
| Rerank | 235.2 ms；1 个候选、1119 字符 |
| 回答 LLM | 1613 输入 / 142 输出 token；2798.4 ms |
| 端到端首字时间 | 2277.6 ms |

`mix` 样本有 6 个候选；最终上下文和输出长度也不同，因此不能把两者的耗时差直接全部
归因于是否调用查询理解 LLM。原始数据：

## 9 题首轮

| 指标 | 结果 |
| --- | ---: |
| API 成功 | 9/9 |
| 端到端首字时间中位数 / P95 | 3.31 / 4.78 秒 |
| 端到端总耗时中位数 / P95 | 3.53 / 4.78 秒 |
| 单客户端完成量 | 17.49 题/分钟，包含 1 题缓存命中 |
| 实际调用最终生成模型 | 8/9 |
| 最终生成输入 token 中位数 / 范围 | 1497.5 / 1037–1996，基于 8 题 |
| 最终生成输出 token 中位数 / 范围 | 83.5 / 4–117，基于 8 题 |
| 模型原生解码速度中位数 | 83.4 token/秒，基于 8 题 |

SDK09 未调用模型，LightRAG 日志出现一次 `Query cache hit`；它的 425 ms 不应与实际生成题混算成模型推理性能。仅看 8 道实际生成题，端到端首字时间中位数为 3.42 秒，总耗时中位数为 3.95 秒。BURN11 仅生成 4 token，回答为“无法确认”；这些数字是性能记录，不代表答案正确。

## 另一道新问题的两次 LLM 调用

新问题询问 RM182xMC0 USB 自动测试的枚举、速率和 ADB date 失败条件，命中两次模型调用：

| 阶段 | 输入 token | 输出 token | 模型调用耗时 |
| --- | ---: | ---: | ---: |
| 检索关键词提取 | 690 | 67 | 1.36 秒 |
| 最终回答生成 | 1192 | 176 | 2.90 秒 |
| 两次合计 | 1882 | 243 | 4.26 秒 |

本题端到端首字时间 3.74 秒、总耗时 5.64 秒。模型调用耗时之外还包括检索、embedding、rerank、LightRAG 处理和传输。最终生成的原生解码速度约 84.8 token/秒。关键词结果有独立缓存；命中时不再执行第一次 LLM 调用。完整答案命中查询缓存时，两次调用都可能省去。

本轮是小样本单并发基线，不能据此推断多人并发容量或服务等级目标；后续做容量测试时应固定问题集、重复次数、缓存条件和并发数，并同时检查答案质量。

原始逐题数据：[USB 当前缓存路径](../evals/three-docs-v1/results/qa-performance-usb-stage-20260921.json)、[USB 关闭缓存路径](../evals/three-docs-v1/results/qa-performance-usb-nocache-20260921.json)、[9 题结果](../evals/three-docs-v1/results/qa-performance-20260921.json)、[另一道新问题](../evals/three-docs-v1/results/qa-performance-two-stage-20260921.json)。复测脚本：[benchmark_qa.py](../evals/three-docs-v1/benchmark_qa.py)。
