# RAG 准确性回归：问题、改动和验证范围

更新日期：2026-09-15。本文记录本仓库在 162 的 RK3588 + RK1828、单卡 Qwen3.5-4B 查询服务上，为解决 FT 测试、ROCKRAGCLAW 部署、授权等文档问答的准确性问题所做的迭代。它是实现与回归记录，不宣称已经完成企业级验收。

引用阅读栏另见 [引用预览说明](reference-preview.md)。

## 评测从哪里开始

[评测集 v1](../evals/rag-v1/README.md)包含 40 题：产线测试 16、部署 12、授权 8、证据不足/实时状态边界 4。只有 FT01、FT02、DEP01、AUTH01 是历史用户原问题；其余是文档或历史场景衍生题，不能冒充真实用户日志。`cases.json`记录必答要点、禁止断言和原文摘录，`corpus-snapshot.json`记录建集时的文档内容哈希；`validate.py`校验题目结构和可选的原文摘录存在性。`run_eval.py`串行调用流式接口，保存回答、结构化引用、TTFT、总耗时、错误和原始事件；**正确性、引用支持和完整性仍需人工评分**。

最初同参数的 10 题冒烟基线见 [Hybrid/Mix 对比](../evals/rag-v1/results/hybrid-vs-mix-smoke-20260915.md)：两种模式均无 API 错误，但人工严格初审都只有 1/10 明确通过。Hybrid 有引用题 9/10、Mix 6/10；这不是引用正确率。FT01/FT04 缺 USB 与 ADB 的精确判断分支，DEP01 漏授权、模型和启动，DEP06/AUTH02 漏原文代码命令，FT09 类对比题有事实串位风险。结论是只把默认模式从 Hybrid 切成 Mix 不够。

## 按失败原因做了什么

| 基线问题 | 实施改动 | 主要位置与代表提交 |
| --- | --- | --- |
| 4B 回答容易在编号步骤中途停下，单纯压短又漏必要内容 | 查询改用单卡 Qwen3.5-4B；网关传递模型 `finish_reason`；查询生成上限调整为 256 token，普通生成可到 512；在网关末尾注入“只依据证据、精确抄写命令/路径、回答一次”的约束。 | `core/model-gateway/rk1828_model_gateway.py`、`core/model-gateway/deploy/rk3588.env`；`97de134`、`9e81f78`、`3f88ef0`、`b0e5d28` |
| KG 摘要能被召回，`P!` 文本中的 `CherryUSB ADB`、`speed=5000`、`timestamps:` 或原样命令却进不了生成上下文 | 扩大候选池，增加本地 BM25 词法检索，与向量候选用加权 RRF 融合后再重排；为 USB、产品号/SN、Unix socket、复现步骤加入领域标识符扩展与精确证据加权。 | `rk_lexical_retrieval.py`、`rk_source_policy.py`、相应 Hook；`d53bb39`、`2eec171`、`0b8ccd9`、`3946430`、`ba5dd80` |
| 大 chunk 或混合路径合并把命令所在片段挤掉；3000 token 预算下可能剩 0 个引用 chunk | 从 Markdown 选择有命中行和邻近标题的限长片段；混合合并时保留聚焦片段；若整个 chunk 超预算，裁剪最高排证据而不是直接丢光。 | `rk_lexical_retrieval.py`、`rk_chunk_budget.py`、聚焦合并/预算 Hook；`a30bd15`、`0e4297d`、`ac005b1`、`c5ab61c`、`87949b7` |
| FT1/FIT1/IQC 等多对象对比只取到一节、漏后段动作，或把 `SET_PN` 写进 FT1 | 对比查询按对象标题选择多个章节，再按问题指定维度选行；标题区间限定事实归属，同时保留后段事实和流程动作。 | `rk_lexical_retrieval.py`、网关查询约束；`9811fff`、`b416c5d`、`94e98cc`、`f69e9ed`、`ae8cf3c`、`a09f4df`、`00375ca` |
| 技术方案里旧模型的示例答案或只重复问题的薄片段排名过高 | 重排后降低派生技术方案和缺乏实质证据的短片段分数；保留短命令例外，多个精确标识符同时命中时提升直接原文。 | `rk_source_policy.py`、来源策略 Hook；`44633b1`、`0b8ccd9` |
| 回答短而漏流程、重复输出，或者把静态文档说成当前设备状态 | 按查询意图只应用一种输出契约：原因 1–3 条、命令加一句说明、比较每对象一行、完整复现五个短步骤；明确通则/例外和证据不足边界，禁止补造当前状态。 | `rk1828_model_gateway.py` 与 `test_query_contract.py`；`e63592f`、`833150c`、`89a16d7` |
| 策略已修改但旧答案缓存仍返回先前版本；难以解释候选在哪一阶段被淘汰 | 让答案缓存键包含可配置策略版本；记录融合、重排、最终预算阶段的 chunk ID、排名和分数，不记录完整提问与证据正文。 | `install_lightrag_answer_cache_version_hook.py`、`install_lightrag_retrieval_trace_hook.py`；`a52e0bd`、`4e36dd4` |
| 回答里没有可定位的证据，无法复核其依据 | 最终保留的证据按 chunk 分配结构化引用，并逐步增加回答尾注、阅读页和右侧预览。引用展示的范围与限制见单独文档。 | `rk_chunk_citations.py` 等；`4f2d954`、`4da0a86` 及后续引用预览提交 |

这些改动主要通过固定 LightRAG 版本上的 Hook 安装，未修改知识库中的模型权重。当前部署配置以 `mix` 为默认，`top_k=6`、`chunk_top_k=3`、实体/关系/总上下文预算 `500/300/3000`，rerank 开启；`mix` 的 3000 token 总上限也在服务端实施，避免旧浏览器设置超过 4B 上下文预算。网页默认参数和 API 默认模式随 `6fb84c7` 调整。配置位置是 `core/model-gateway/deploy/lightrag-rk3588.env` 与 `core/model-gateway/deploy/rk3588.env`；板端实际覆盖值应以运行时配置为准。

## 测试后能确认到什么程度

| 阶段 | API/引用观察 | 人工核查与限制 |
| --- | --- | --- |
| 2026-09-15 原始 Hybrid/Mix 10 题基线 | 两者均 10/10 无 API 错误；有引用题分别为 9/10、6/10。Mix 的 TTFT/总耗时中位数约 7.82/9.44 秒。 | 按评测集严格规则初审，两者均仅 1/10 明确通过；模式切换本身不是准确性修复。 |
| Engineered Mix v30 同一组 10 题 | 10/10 无 API 错误、10/10 至少有一条结构化引用；TTFT/总耗时中位数约 6.47/7.75 秒。 | [v33 回归记录](../evals/rag-v1/results/engineered-mix-v33-20260915.md)逐项人工核查了 USB/ADB 分支、日志位置、控制台命令、授权、实时状态边界等；“有引用”仍不等于逐句有据。 |
| v33 复现问题补测 | DEP01 一题无 API 错误，TTFT 约 6.72 秒、总耗时约 10.59 秒。 | 补上环境、授权、部署、模型和启动验证锚点；这一题不能替代 40 题全量回归。 |

以上延迟包含排队、检索、生成并可能命中既有缓存；基线先跑 Hybrid 后跑 Mix，未做严格随机化或冷启动控制，**不能把中位数差异单独归因为某一个改动**。第一次重启两个服务后的请求可能因 embedding/reranker 懒加载耗时约 16–27 秒。网关已传递 `finish_reason`，但当前 LightRAG 的 NDJSON 评测接口尚未将其暴露给 `run_eval.py`，评测结果中该字段为未采集，不应把“前端有字”误判为正常结束。

代码级回归在本次文档整理时通过：模型网关 12 项、LightRAG 扩展 33 项；`validate.py`结构校验确认 40 题无格式错误。它们不是模型语义评分。仓库保存的是 10 题检查的 Markdown 结论；逐题 JSON 位于 `evals/rag-v1/results/` 且被忽略，不应假设其他克隆仓库自动拥有这些原始结果。

## 仍未完成的验收

- 尚未把优化后的版本按六维评分规则完整跑完并人工审核 40 题，也没有独立盲测集或领域专家最终签字；固定词表对新领域的收益不能从这 10 题外推。
- 结构化 `References` 是最终证据 chunk 清单，不是回答每一句的已验证归因。引用支持率、结论引用覆盖率、原文定位率仍需单独核查。
- PDF 授权文档存在解析导致的下划线和命令乱码；精确命令需要人工对照原始 PDF。静态知识库不能证明当前设备配置、实时故障或性能。
- 运行中的优化服务是 transient systemd 单元；重启持久化不属于这次准确性回归结论。

复测当前 `mix` 冒烟集时应显式指定模式，因为评测脚本的 CLI 默认值保留为 `hybrid`，用于重现最初基线：

```bash
bash evals/rag-v1/run-via-162.sh --smoke --mode mix --label mix-regression
```

完整 40 题去掉 `--smoke`。运行后先看原始回答与证据，再人工评分；HTTP 10/10 或 References 10/10 都不是准确性通过率。
