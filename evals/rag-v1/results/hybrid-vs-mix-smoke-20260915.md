# Hybrid 与 Mix 冒烟基线对比（2026-09-15）

## 测试条件

- 同一套 10 题：FT01、FT04、FT06、FT07、DEP01、DEP06、AUTH02、AUTH08、NEG01、NEG02。
- 其余请求参数相同：top_k=6、chunk_top_k=3、实体/关系/总预算=500/300/3000、rerank 开启、流式输出、空会话历史。
- Hybrid 先跑，Mix 后跑；沿用既有 LightRAG 缓存，没有清空抽取缓存。延迟可作为本次基线，不能视为严格冷启动对比。
- 原始结果：`hybrid-baseline-20260915-094505+0800.json`、`mix-baseline-20260915-094643+0800.json`。

## 逐题结论

| 题目 | Hybrid | Mix |
| --- | --- | --- |
| FT01 USB 原因 | 只给日志定位，缺设备名、速率与 ADB 判断分支 | 同样缺核心原因，并返回无相关文档 |
| FT04 timestamps 分支 | 未识别应归为 ADB | 未识别应归为 ADB |
| FT06 日志位置和定位 | 找到 Errors/测试段标记，但日志目录回答不准确 | 找到 KG 与文本原文，但仍漏掉上位机 LOG/SN 日志位置 |
| FT07 虚拟控制台 | 只有 `rknn-console`，漏 `rk1820` 参数 | 正确返回 `rknn-console rk1820` 和 Ctrl+X，文本引用支持命令 |
| DEP01 完整复现 | 只有环境和部署，漏授权、模型、启动和验证 | 与 Hybrid 基本相同，仍不完整 |
| DEP06 Unix socket 状态 | 错误回答不能查看，改去查 OpenClaw | 与 Hybrid 相同，未召回包含 curl 命令的文本块 |
| AUTH02 账户授权命令 | 未给出要求的完整命令 | 与 Hybrid 相同，未召回代码块 |
| AUTH08 重复授权例外 | 理解到加密狗风险，但没有引用 | 语义基本正确；引用只支持一般规则，没有覆盖 USB 加密狗例外 |
| NEG01 是否确认线坏 | 正确拒绝无依据确认，并建议看测试日志 | 正确拒绝，但增加了与线缆诊断无关的 `rkdevice_info` 建议 |
| NEG02 当前模型/卡数 | 正确说明静态知识库不能确定；引用了无关授权 PDF | 正确说明不能确定，但错误建议从 `device.inf` 获取模型和卡数 |

按 cases.json 的严格规则（所有适用维度均满足）人工初审，两种模式都只有 1/10 明确通过：Hybrid 是 NEG01，Mix 是 FT07。这不是最终专家评分，但足以证明当前版本不能仅靠切换模式达到验收要求。

## 决策

知识库有大量 `P!` 文本内容和精确命令，长期默认模式应以 Mix 为目标，因为它能够直接使用原始文本检索。本轮 Mix 已在 FT07 显示出这一优势。

当前不应把“切成 Mix”当作修复完成：在 3000 token 总预算下，FT01/FT04 的最终引用为 0，DEP06/AUTH02 仍只命中 KG 摘要。下一步应先记录候选 chunk、rerank 分数和淘汰原因，再为直接证据保留上下文预算；修复后用同一 10 题重新比较。
